# Key files: Split git layout (command, doctor, relayout)

[Subsystem index](../KEY_FILES.md) · [format core](core-services-2-continued.md) (`src/core/split-layout/`). Read only the entries relevant to your change.
Current behavior and load-bearing invariants; history belongs in Git and CHANGELOG.

- `src/commands/pages-split-storage.ts` — `gbrain pages split-storage <slug> [--source <id>] [--apply] [--json] [--resolve-head keep-edit|discard]` (Wave B PR 5, spec §9 option B; trusted local CLI only, never an MCP op, never run on upgrade). `parseSplitStorageArgs` is strict (the `pages split-storage` row of `src/cli/strict-args.ts`; `invalid_params`, exit 2). `previewSplitStorage` reads the stored page (`serializePageToMarkdown`, or `unreadPageFile` streamed from the segments for a segmented page) and the files at its canonical path through `sourceContext`/`canonicalPath` (`ghost-pages.ts`; another host gets `not_owner_host`), and reports `current` (`missing`, `single`, `split` with parts and verdict), `matches_render` (byte equality with the render; a put_page-written file can differ only in frontmatter key order), `threshold_bytes`, and `target`: the head and parts `planSplit` cuts with unchanged parts, writes and removals. It writes nothing: the plan's staged copy is disposed before it returns. `blocked` names `canonical_file_missing`, `split_head_modified` (resolve first), `split_page_incomplete` (restore parts from Git) or a `SplitLayoutError` code. `--apply` refuses a blocked preview (`applyRefusal`), publishes and then reads the files back (`laid_out`; exit 1 when they are not in the planned layout). Layout and `discard` publish the `managed_maintenance_split_relayout` intent (`relayout.ts`) bound to the previewed revision, because an unchanged page write is a no-op that publishes no file; `keep-edit` uploads the kept file (`writeKeptEdit`) as a `put_page` replacement at that revision. Test: `test/split-layout-command.test.ts` (its `--apply` layout cases wait for the write path to lay out head and parts).
- `src/core/split-layout/relayout.ts` — `prepareSplitRelayout`, the preparer of `managed_maintenance_split_relayout` (dispatched by `prepared-maintenance.ts`): local only, the live page at the intent's `expected_revision` (`changed_since_preview` otherwise), its render handed to `prepareFileTarget` so the write path lays the file out and the coordinator re-checks the revision; the page row is untouched (`status: relaid_out`), and a page with no canonical file refuses `invalid_params`.
- `src/core/split-layout/disk-layout.ts` — read-only view of a canonical path: `readHead` (bounded: a file larger than any head is read only in its first frontmatter window, `O_NOFOLLOW`), `readCanonicalLayout` (`missing` / `single` / `split` with `verifyParts`' verdict and the parts directory entries) and `partsDirEntries`.
- `src/core/split-layout/page-file.ts` — the page file a reader outside the publication door sees at a canonical path: `readPageFile(path)` returns an ordinary file's bytes, or for a split head the reassembled F' (bounded by `PAGE_FILE_MEMORY_MAX_BYTES`, the door's in-memory ceiling) with the head's own bytes; `pageFileSha256(path)` streams F''s SHA-256 (and the head's). A head whose parts do not verify, or an F' over the bound, is a typed hold (`split_page_incomplete`, `split_head_modified`, `split_page_too_large`) with a message naming the path and the fix, never a short page.
- `src/core/split-layout/resolve-head.ts` — `editedLead` (the head body without its notice line) and `writeKeptEdit`: head frontmatter without `gbrain_parts` + edited lead + B[lead_bytes:] from the parts in manifest order, checked against `content_hash` while copied, written to a private scratch file and removed on failure.
- `src/commands/doctor/checks/split-layout.ts` — `splitLayoutEntry` (BRAIN, after `fence_integrity`, before `search_mode`) emits `split_layout` (stray `.<name>.gbparts` directories: `no_head`, `head_not_split`, `not_in_manifest`; and held split pages, `SPLIT_HOLD_CODES` holds of each source's current incarnation) and `oversize_canonical_file` (a single `.md` over `sync.max_file_bytes`; fix: the split-storage preview). Both warn at most. One walk per owned checkout, `SPLIT_WALK_ENTRY_LIMIT` (100,000) entries in total plus a deadline, dot directories and `node_modules` skipped, only oversize heads read; a remote caller gets counts only. Test: `test/split-layout-doctor.test.ts`.
