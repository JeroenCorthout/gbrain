# Key files: Split git layout (command, doctor, relayout)

[Subsystem index](../KEY_FILES.md) · [format core](core-services-2-continued.md) (`src/core/split-layout/`). Read only the entries relevant to your change.
Current behavior and load-bearing invariants; history belongs in Git and CHANGELOG.

- `src/commands/pages-split-storage.ts` — `gbrain pages split-storage <slug> [--source <id>] [--apply] [--json] [--resolve-head keep-edit|discard]` (Wave B PR 5, spec §9 option B; trusted local CLI only, never an MCP op, never run on upgrade). `parseSplitStorageArgs` is strict (the `pages split-storage` row of `src/cli/strict-args.ts`; `invalid_params`, exit 2). `previewSplitStorage` reads the stored page (`serializePageToMarkdown`, or `unreadPageFile` streamed from the segments for a segmented page) and the files at its canonical path through `sourceContext`/`canonicalPath` (`ghost-pages.ts`; another host gets `not_owner_host`), and reports `current` (`missing`, `single`, `split` with parts and verdict), `matches_render` (byte equality with the render; a put_page-written file can differ only in frontmatter key order), `threshold_bytes`, and `target`: the head and parts `planSplit` cuts with unchanged parts, writes and removals. It writes nothing: the plan's staged copy is disposed before it returns. `blocked` names `canonical_file_missing`, `split_head_modified` (resolve first), `split_page_incomplete` (restore parts from Git) or a `SplitLayoutError` code. `--apply` refuses a blocked preview (`applyRefusal`), publishes and then reads the files back (`laid_out`; exit 1 when they are not in the planned layout). Layout and `discard` publish the `managed_maintenance_split_relayout` intent (`relayout.ts`) bound to the previewed revision, because an unchanged page write is a no-op that publishes no file; `keep-edit` uploads the kept file (`writeKeptEdit`) as a `put_page` replacement at that revision. Test: `test/split-layout-command.test.ts` (its `--apply` layout cases wait for the write path to lay out head and parts).
- `src/core/split-layout/git-page-file.ts` — the page file a split head stands for at a Git revision, from blobs: `pageFileAtRevision(path, revision, head, parts)` takes the head blob and the parts directory's blobs at that revision (keyed by manifest path, matched by part file name, so a head moved with its directory reads) and returns `readPageFile`'s shape: F' when every listed part matches its size and SHA-256, the parts hash to `content_hash` and the head body to `lead_sha256`; else the hold `split_page_incomplete` (missing, unlisted or mismatched parts) or `split_head_modified`; over the in-memory bound, `split_page_too_large`. Used by the git-gap census (`sources-git-gap.ts`: a committed split page compares as F', a head that does not reassemble is `unparseable`) and `repair overwritten-edits` (`committedPageFile`). Test: `test/split-layout-git-blobs.test.ts`.
- `src/core/split-layout/relayout.ts` — `prepareSplitRelayout`, the preparer of `managed_maintenance_split_relayout` (dispatched by `prepared-maintenance.ts`): local only, the live page at the intent's `expected_revision` (`changed_since_preview` otherwise), its render handed to `prepareFileTarget` so the write path lays the file out and the coordinator re-checks the revision; the page row is untouched (`status: relaid_out`), and a page with no canonical file refuses `invalid_params`.
- `src/core/split-layout/disk-layout.ts` — read-only view of a canonical path: `readHead` (bounded: a file larger than any head is read only in its first frontmatter window, `O_NOFOLLOW`), `readCanonicalLayout` (`missing` / `single` / `split` with `verifyParts`' verdict and the parts directory entries) and `partsDirEntries`.
- `src/core/split-layout/page-file.ts` — the page file a reader outside the publication door sees at a canonical path: `readPageFile(path)` returns an ordinary file's bytes, or for a split head the reassembled F' (bounded by `PAGE_FILE_MEMORY_MAX_BYTES`, the door's in-memory ceiling) with the head's own bytes; `pageFileSha256(path)` streams F''s SHA-256 (and the head's); `withPageFileOnDisk(path, read)` hands a streaming reader the path itself, or a private scratch copy of F' (copied part by part, unbounded, removed once `read` settles). A head whose parts do not verify, or an F' over the bound, is a typed hold (`split_page_incomplete`, `split_head_modified`, `split_page_too_large`) with a message naming the path and the fix, never a short page. `readPageText(path)` is `readPageFile` as text for a reader that skips what it cannot read: a hold throws its message.
- `src/core/split-layout/resolve-head.ts` — `editedLead` (the head body without its notice line) and `writeKeptEdit`: head frontmatter without `gbrain_parts` + edited lead + B[lead_bytes:] from the parts in manifest order (each at `partFilePath`, the head's own parts directory), checked against `content_hash` while copied, written to a private scratch file and removed on failure.
- `src/commands/doctor/checks/split-layout.ts` — `splitLayoutEntry` (BRAIN, after `fence_integrity`, before `search_mode`) emits `split_layout` (stray `.<name>.gbparts` directories: `no_head`, `head_not_split`; and held split pages, `SPLIT_HOLD_CODES` holds of each source's current incarnation) and `oversize_canonical_file` (a single `.md` over `sync.max_file_bytes`; fix: the split-storage preview). Both warn at most. One walk per owned checkout, `SPLIT_WALK_ENTRY_LIMIT` (100,000) entries in total plus a deadline, dot directories and `node_modules` skipped, only oversize heads read; a remote caller gets counts only. `split_layout` also counts live pages an older gbrain stored from their split head (top-level `gbrain_parts` in the stored frontmatter, `stale_split_imports` / `stale_sample`) and names `gbrain sync --source <id> --no-pull`; it never rebuilds them. Tests: `test/split-layout-doctor.test.ts`, `test/split-layout-managed-sync.test.ts`.
- `src/core/persistence/split-head-admission.ts` — `assertNoReservedPartsKey`: put_page, capture and edit_page admission, and the commit_page_upload preparation (persistence/page-upload.ts `prepareStagedUpload`), refuse content whose frontmatter declares a top-level `gbrain_parts` key (`split_head_content`, the code the publication door raises in `split-files.ts`). Kept out of `split-layout/head.ts` so the head parser stays outside the operation-error graph the embedded chunker smoketest compiles. Test: `test/split-layout-reserved-key.test.ts`.
- `src/core/persistence/sync-split.ts` (stale imports) — `staleSplitImports` (live pages with top-level `gbrain_parts` in the stored frontmatter, `frontmatter ? 'gbrain_parts'` on the GIN index `idx_pages_frontmatter`, at most `STALE_SPLIT_SCAN_LIMIT` per run) and `withSplitRebuilds` (the `split_pages_rebuilt` result field, slugs omitted for a remote caller). Managed sync makes such a page block the idle pass (`stale_split_import`) and classify as `import`; classic sync re-screens it (`planStaleSplitRescreen` in `src/commands/sync/holds.ts`). Tests: `test/split-layout-managed-sync.test.ts`, `test/split-layout-sync.test.ts`.
- Split readings (`persistence/split-files.ts` `readSplitHead`, `split-layout/read.ts` `openSplitPage`, `persistence/sync-split.ts` `freezeSplitPage`) — each returns `plain` (an ordinary file), `split` (F' reassembled from verified parts) or `split_invalid` (a declared head that does not verify: `split_page_incomplete`, including a missing parts directory or an oversize head, or `split_head_modified`). A declared head is never read as an ordinary file: `prepareFileTarget` refuses `split_invalid` before any comparison or removal (`splitInvalidRefusal`: the drift refusal, `source_changed` / `file_database_drift`, with the split code as its `reason` and the receipt's `error_detail.origin`), unless the write is a modified head's resolution; import and sync hold it. A head an older gbrain imported as the page heals through sync once its parts verify. Test: `test/split-layout-invalid-head.test.ts`.
- Split commit path set (`persistence/effect-git.ts` `splitUnitPaths`) — the one list every commit of a split page uses: the strict door commit (`coordinator.ts`) and landed-commit recovery (`split-files.ts` `splitLandedCommit`, which also requires the commit's tree to hold every manifest part as on disk and nothing else in the parts directory). It returns the head, every part the head on disk lists (verified; kept parts included, so a part Git never had lands with the head) and every other path Git holds under the parts directory that is gone from disk (removed); `staged` accepts the publication's staging files there. Tests: `test/split-layout-unit-commit.test.ts`, and `test/split-layout-unit-paths-conformance.test.ts` (no door function commits or checks a split page's commit without it; planted bypasses).
- `src/core/persistence/split-unit-guard.ts` — Wave B PR 5 (option B): the one refusal predicate for a split page's files. `assertSplitUnitMutable({ root, path, route, strict, … })` runs before any write, commit, removal or restoration of a path that may be in a split unit; `splitUnitRefusals` / `splitUnitMembers` answer a whole sweep with one read-only Git step per root (`effect-git.ts` `gitReadOnly`, none outside a work tree; disk is checked first). Only the strict door (`route: 'door'`, `strict: true`) may change a unit, and it refuses an index flag on the head or its parts directory, a converting Git attribute or core.autocrlf, and a unit whose HEAD, index and disk differ. Every other route refuses as soon as the path is in a unit. Every refusal is `split_page_unsupported` with one reason of `SPLIT_UNSUPPORTED_REASONS` (`non_strict_source`, `outside_door`, `index_flag`, `git_attribute`, `unit_diverged`, `recovery_unit_changed`) and its own fix (`splitPageUnsupportedAdvice`). Tests: `test/split-unit-guard.test.ts`, `test/split-unit-guard-sync.test.ts`, `test/split-layout-door-refusals.test.ts`; the writer census (`test/split-layout-writer-census.test.ts`) fails on a route outside the door that skips it.
- `src/core/persistence/split-files.ts`: Wave B PR 5 (split git layout, spec §9 option B), the write path. Inside `publishMutation`, under the worktree lock and before the recovery record, `splitPublicationTargets` turns a page file target whose content is over `sync.max_file_bytes` into the unit: the head becomes the target's content, part targets are the new manifest's new or changed parts (a part already on disk with the same name and bytes is not rewritten, so an append writes the head and the parts from the old last one on), and every other file of the parts directory is a removal; a page at or under the threshold, or a removal, removes every part and then the empty directory (`removeEmptyPartsDir`). One `SplitRecoveryRecord` (`model.ts`: `{ version: 3, target: 'page_split', files }`, head first, each with single-file staging; v278 (provisional) lets the request guard accept it on a page request) covers every file; every prior file it replaces or removes is named by its staged before-copy (path, SHA-256), never embedded. Only a git-canonical source plans a split (`publishMutation` calls `splitPublicationTargets` only when `binding.canonical_git` is true, and never for a `managed_file_repair`); it commits every file in one door commit (`commitThroughDoor`, the note on the head) and the Git effect only pushes (`push_only`). A non-strict source writes one file at any size, as master does. `recoverPublication` (coordinator.ts) recovers the record as one unit, after `assertSplitRecoveryBinding`: it checks every staged before-copy (`verifyBeforeStage`) before it restores any file, so a corrupt before-copy blocks with no file changed, then restores every file to its prior bytes, or keeps every file when `splitLandedCommit` finds the door commit after the record's door head holding each file as published, and stamps `persistence.git_commit` with `landed_before_row` as for a single file (#7521); bytes matching neither side block the request (`unexpected_file_bytes`). `readSplitHead` lets `prepareFileTarget` compare a verified head as the page file its parts reassemble to while expecting the head's bytes (split-layout.md), and `refusePartFileTarget` (`file-claims.ts`) refuses a target inside a parts directory (`source_changed`, detail `split_part_path`). A group publication leaves a target that may take the layout (`mayTakeSplitLayout`) to `publishMutation`, and `repair stuck-recovery` refuses a split record (`recovery-resolve.ts`). An older binary refuses both: it knows recovery versions 1 and 2 only, so it refuses the record `recovery_version_unsupported` (the upgrade fix) before touching a file, and `targetedWithdrawalEffect` throws `withdrawal_provenance` on the version 3 effect, so it never commits a head without its parts. Publication refuses content that declares a top-level `gbrain_parts` key (`split_head_content`: a head written back as the page), a parts directory holding anything but part files (`split_parts_unexpected`), and any part that differs from the parts the write was prepared against (`expectedParts`, rechecked under the lock: `source_changed`); every part takes the head's `publishMode`, else the head file's prior mode (a 0600 page keeps 0600 parts; a mode granting nothing to group or other creates the parts directory 0700). The Git effect never commits a split unit: `commitGitTargets` refuses every unit path through `splitUnitRefusals` (`split_page_unsupported`, reason `outside_door` on a strict source, `non_strict_source` otherwise), and `effects.ts` parks it, like `git_target_ignored` and `split_page_incomplete`, on the first attempt with the reason and fix on the parked target. `splitLandedCommit` reads only an empty range as not landed: a Git failure refuses `git_unavailable` and keeps the record fenced. Tests: `test/split-layout-publish.test.ts`, `test/split-layout-publish-recovery.test.ts`, `test/split-layout-publish-drift.test.ts`, `test/split-layout-publish-mode.test.ts`, `test/split-layout-parts-unexpected.test.ts`, `test/split-layout-head-content.test.ts`, `test/split-layout-git-effect-unit.test.ts`, `test/split-layout-door-refusals.test.ts`, `test/split-layout-lifecycle.test.ts`.
- Withdrawal mirror of a split page (`effects.ts` `mirrorPage`, Wave B PR 5 option B): a mirror is a route outside the door, so a target in a split unit (`outsideDoorRefusal`, route `mirror`) is passed by with `split_page_unsupported`: `materializeAndAdvance` and `skipTarget` record it in the effect's skipped targets (protocol 2, `declarePersistenceProtocol`) and the head, every part and HEAD stay; a one-file page is mirrored and committed at any size. Test: `test/split-layout-withdrawal-mirror.test.ts` (both engines).
