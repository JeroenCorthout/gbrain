## Shared-checkout git writer

- `src/core/git/commit-push.ts` + `src/core/git/commit-guard.ts` — writer safety in a shared checkout (#7381). `integrate` replaces the tip 3-way merge when any local commit is patch-equivalent to an upstream one (`rev-list --cherry-mark`): it replays the local commits onto the remote tip in memory (`merge-tree --merge-base` on git 2.40+, a 3-way `read-tree` otherwise), leaving out the equivalent ones and clean merges, so a copy the remote edited never conflicts and one it reverted is never re-applied; the merge message lists what it left out. `supersededPaths` resolves a content conflict to ours when the remote's blob is one the same path held earlier in ours' history (last 200 commits touching it) and a different blob replaced it there; the push reports them as `superseded_remote_paths`, and `integrate_conflict` lists only the rest (`detail.superseded` names them). `commitPaths` refuses a path outside the source roots (`configuredSourceRoots`, git config `gbrain.sourceRoot`, recorded by `sources harden`'s `recordSourceRoot`) and a file another writer staged under a named directory (`commit_prestaged_paths`), and restores the exact index entries (`update-index --index-info`) when git refuses the commit. Every commit gbrain makes carries `GBRAIN_COMMIT_VIA=<lock path>`. `commitPathsLocked` (write-through) never commits without the lock: a busy lock or refused commit notes the file in `brain-writethrough-pending.log` (git dir, O_APPEND lines), which the next locked write-through and `commit-push --pending` commit and `settlePending` prunes. A publish refuses local non-merge commits outside the roots (`commit_outside_source_root`; `--allow-outside-source-root` lifts both refusals, and `sources harden` passes it for its root scaffolding). - `src/commands/doctor/checks/git-writer.ts` — `checkout_lagging`, `dirty_age`, `commits_outside_source_root`, `quarantined_changes` (#7381, brain category, after `git_convergence`): over the unmanaged source checkouts with an upstream (`sourceRoots` from git-convergence, grouped by toplevel with each source's toplevel-relative root), never fetching, every git call bounded at 5 s. Lagging warns when `HEAD..@{u}` holds a commit over an hour old (fix: `gbrain git commit-push --pull --path <top>`, agent). Dirty age warns on pending write-through files older than 30 minutes (`pendingWriteThroughStillDirty`; fix: `commit-push --pending`, agent) and on files staged that long (ask_user: unstage or commit by name). Outside-root warns on unpushed non-merge commits that change files outside the DB source roots plus `gbrain.sourceRoot` (`localCommitsOutsideRoots`; ask_user fix with `--allow-outside-source-root`), and says when the checkout has no root recorded. - `src/core/git/maintenance.ts` + `src/core/cycle/git-maintenance.ts` + `src/commands/doctor/checks/git-repo-health.ts` — Git object-store maintenance for strict sources and hosted bare repositories (Wave C 1C, G7), run without the writer lock under its own `<git common dir>/gbrain-maintenance.lock` (busy: `git_maintenance_busy`) and recorded in `gbrain-maintenance.json`. `planMaintenance(repo)` reads `repoStats` (count-objects), the record, `userScheduledMaintenance` (`maintenance.auto`/`maintenance.strategy`/`maintenance.repo`) and, for a daily run only, `git prune --dry-run`, and picks `repack` (loose past 256 MiB or grown 64 MiB: geometric repack + prune-packed) or `daily` (prune past `2.weeks.ago` first, then a cruft repack with the same expiration, then prune-packed); `runMaintenance` runs the steps (failure: `git_maintenance_failed`), starting none once the cycle's signal or deadline is reached and bounding each step's timeout by the deadline. The `git_maintenance` cycle phase (global, after `unindexed_files` in `REPAIR_LANE_PHASES`) runs the automatic plan per strict source unless `git.maintenance` is `off` or the user scheduled git's own maintenance; `gbrain git maintenance [--source|--path] [--dry-run|--apply] [--json]` (`src/commands/git.ts`) previews by default. Doctor `git_repo_health` warns on loose bytes, pack count, a failed last run and 2 GB packed with a github.com remote; its fix (pinned `--source` through `routes_subcommands`) is the preview, then `--apply`. It also runs `git fsck --connectivity-only` per source under one shared bound (`GBRAIN_DOCTOR_GIT_FSCK_TIMEOUT_MS`, default 20 s, capped at the entry deadline) and fails with `git_objects_missing` (a `report` fix with the restore steps) when an object HEAD, a ref or the index needs is gone; an unfinished walk is reported as not checked. Tests: `test/git-maintenance.test.ts` (both engines).
