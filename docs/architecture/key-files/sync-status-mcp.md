- `src/commands/sync/status-document.ts` + `src/commands/repair-agent.ts` + `src/core/ops/mcp-twin.ts` + `src/core/repair/agent-apply-receipts.ts` — GBRA-133 PR 3: sync status and repairs over MCP. `buildSyncStatusDocument(engine, sourceId, { detail, viewer })` is the one `sync status` document for `gbrain sync status --json` and the MCP `sync_status` op (identical field names): `readSyncStatus` plus capacity, freshness, the notifier block (the remote projection for http), `autofix` (`readAutofixState` in `src/core/autofix/state.ts`: receipts, pending repairs and switches; an agent-facing viewer gets the remote projection, with withheld paths left out before counting) and, per hold, `item_id` (`<source>:<path>:<code>:<upstream version[0:12]>`) with `preview` / `apply` / `verify` actions (`holdItemActions`; `apply` is null when a person decides). Every action is rendered through `renderFor`, which attaches MCP twins (`withMcpTwins` / `mcpTwin`: `gbrain repair <kind>` maps to `repair_preview`, or `repair_apply` when `--apply --expect` is given; `gbrain sync status` / `sync unblock` / `sync --source` / `sources status <id>` / `write-request -- <id>` to their tools) so `deriveNext` renders `run` over stdio, and for http relays the exact local command to the brain host (`hostRelay`, no MCP twin). For an agent-facing viewer, holds naming a private page (by page row, else a regex scan of the held file's frontmatter, `heldFilePrivate`) or a slug outside the client's grant are withheld before projection and counted in `holds_withheld`; `scrub` replaces any other string naming them. `opViewer(ctx)` builds the viewer from an op context; `syncStatusPointer` is the read step `sources_status` and `get_status_snapshot` carry. `repair-agent.ts` runs the ops `repair_preview`, `repair_apply` and `sync_unblock` (`src/core/ops/sync-status.ts`): params under the CLI's names become the exact `gbrain repair <kind>` argv (`repairArgvFromParams`, validated by `parseRepairArgs`), run through the same runner or `runContentLane` (`content`: one hash per lane kind, comma-joined); the preview hash is the kind's own, else a digest of the dry run (`dryRunDigest`). Apply runs only for an explicit actor (`local_agent` over stdio or `local_cli`; http refuses `permission_denied` / `remote_apply_unsupported`), reconciles the last apply (`reconcileAgentApplies`; still pending refuses `write_pending`), recomputes the preview (`preview_changed` unless `expect` equals it), refuses an item naming a page the caller cannot read (`withheld_items`), refuses `confirmation_required` without `yes` (the fix is the exact call), and records a receipt (`recordAgentApply`: op_checkpoints op `repair-agent-apply`, fingerprint `<source>:<incarnation>`, last 20, codes, paths, hashes and request ids only). `sync_unblock` binds `unblockSync`'s preview to a digest of each hold's upstream version and the planned actions. `stale-atoms` and `extractor-facts` refuse `trusted_local_only` (ENG-O13). Remote apply is not built. Test: `test/pathological/s-agent-repair-loop.test.ts` (+ `test/e2e/s-agent-repair-loop-postgres.test.ts`).
